# 0194 — A reply to one of the assistant's own messages is the recognized command

Date: 2026-08-31, with the message-retraction unit.

## Context

Decision 0083 settled which shapes of the moderation bot's deletion command
the assistant recognizes. It listed a reply to one of the assistant's own
messages among the shapes that mirror nothing and record as ordinary messages,
and it was right on the tree it was written against: that reply variant carried
no identifier at all, so nothing could be named and nothing could follow.

Two things changed under it. The reply variant now names which of the
assistant's own messages was replied to, and her sends record what the platform
took. The command therefore HAS an effect on that reply, which is exactly the
condition 0083's own reasoning attaches recognition to.

## Decision

An administrator's deletion command replying to one of the assistant's own
messages is a RECOGNIZED command. The row records with the command stamp: no
debt, no budget slot, no model turn, nothing said — the same treatment every
other recognized shape gets, and the treatment 0083 already gives an
administrator's command whose target the store never held.

Recognition still reads the message alone and never the store, which is 0083's
principle unchanged and the reason it holds here. Whether a delivery resolves,
and whether a retraction follows, is decided afterwards: a reply the platform
carried no identifier for, and one naming a message no delivery was recorded
for, are both recognized and both retract nothing.

A NON-administrator's deletion command is unchanged in every case. It is not
recognized, it records as an ordinary message, and — replying to the assistant
— it is still addressed and still answered, exactly as before.

The earlier decision's own document stays unedited. This record is the
amendment, which is how a repository keeps one voice: a document reads as one
present-tense description, and the history of what it used to say lives in the
decisions and in the version history.

## Rejected alternatives

- **Editing decision 0083 in place.** Its wording describes the tree it shipped
  against, where the reply variant genuinely carried nothing to name, and
  rewriting it would erase the reason its listing was correct then.
- **Keeping the reply unrecognized and stamping it only when a delivery
  resolves.** The stamp would then follow store state, so two identical
  requests would record as different kinds — the exact alternative 0083
  rejected — and every unresolvable one would summon a model turn, because a
  reply to the assistant always arrives addressed.
- **Recognizing every sender's deletion command on a reply to her.** It would
  silence a member's ordinary message to the assistant, which 0083 deliberately
  keeps ordinary and answered.
