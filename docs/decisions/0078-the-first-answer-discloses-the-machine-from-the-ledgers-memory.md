# The first answer discloses the machine, from the ledger's own memory

Date: 2026-08-23. Unit 12, the first-interaction disclosure.

The AI Act's transparency duty (Article 50(1) with 50(5), the Commission's
guidelines paras 37, 38 and 143) requires the system itself to inform each
natural person, clearly, at the latest at their first interaction. The
assistant discharges it mechanically: the first answer to each person opens
with the fixed disclosure line.

The fact "has this person ever been answered here" is ledger-derivable, so
no table and no flag stores it — the ledger IS the memory. An answer's
summoning people are read through the same debt-origin walk every
per-person fact uses (decision 0043's machinery), several co-summoners each
checked, and the line shows if ANY of them is new — an absorbed newcomer
included. A person counts as introduced exactly when an earlier answer they
co-summoned opens with the line. The stored line marks the handoff, not the
arrival: an answer lost before the edge's read introduces nobody and the
next answer carries the line, but a reply whose every send attempt fails is
dropped after the line was committed — the same accepted loss the report
delivery records — and that person stands introduced although the line
never reached them. The window is one handoff wide and the failure total
send failure only; stated plainly rather than papered over, and the next
answer is bare rather than doubled, the accepted direction.

Per person, not per conversation: para 143 attaches the duty to the natural
person, so a person introduced in one channel is not introduced again in
another. A person returning after full deletion resolves to a fresh
principal id no stored answer names — the line shows again, correct in both
directions: the store genuinely does not know them, and the duty resets
with the erased memory. A person whose opt-out keeps the emptied identity
stub keeps their principal id, and with it their introduction — the duty
was met at their real first interaction and the stub is precisely the
memory that they were here.

Unreadable provenance folds TOWARD the line: an answer whose summoners
cannot be read is introduced as if everyone were new, because a repeated
line is harmless and a skipped first one is the violation — the inverse of
tool admission's downward fold, for the inverse duty.

## Rejected alternatives

- **A disclosed-flag on the identity row.** A second copy of a derivable
  fact, and erasure would have to decide what deleting it means. The
  ledger already knows.
- **A per-conversation line.** Para 143 attaches the duty to the person;
  a per-conversation line would re-introduce the assistant to people who
  know it and, worse, structure the fact in the wrong table.
- **Disclosure as its own message.** Two sends where one line does it,
  and a flood surface: every first contact would cost the channel an
  extra message.
